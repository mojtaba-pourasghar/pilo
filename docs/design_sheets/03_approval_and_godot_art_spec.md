# تأیید طرح‌ها + مشخصات فنی هنر برای Godot (قانون تولید)

## ۱. تأیید صاحب پروژه (۱۶ نوامبر ۲۰۲۶) — ✅ مورد تأیید است
صاحب پروژه صریحاً اعلام کرد:
- **همهٔ طرح‌هایی که با «زبان بصری ذخیره‌شده» ساخته می‌شوند مورد تأیید صاحب‌پروژه‌اند** ([`00_style_lock.md`](00_style_lock.md) + [`02_style_prompt.md`](02_style_prompt.md)).
- مدیر پروژه **هر پارت را در صورت نیاز دوباره طراحی می‌کند** و برای تأیید سؤال نمی‌پرسد.
- هر چه مدیر در Canva می‌سازد، صاحب پروژه **نسخهٔ کامل را می‌فرستد**؛ مدیر **برش می‌دهد**، در مخزن می‌گذارد و طرح بعدی را آماده می‌کند تا همه تمام شود.
- **شرط:** بازی با **تصویر طرح برش‌خورده** ساخته می‌شود و هر صفحه در بازی با **اسکرین‌شات کنار طرح** مقایسه می‌شود (قانون CLAUDE.md).

### معنا برای Claude Code
هر طرح (شیت، صحنه، صفحهٔ رابط) که در `assets/art/<part>/` یا `assets/reference/` هست و در [`CONCEPT_SPRITES.md`](CONCEPT_SPRITES.md) / [`SCREEN_DESIGNS.md`](SCREEN_DESIGNS.md) ثبت شده، **«طرح تأییدشده»** حساب می‌شود و ساخت صفحه ممنوع نیست. صفحه‌ای که طرحش نیامده ساخته نمی‌شود (بدون تغییر).

## ۲. اصول فنی Godot (برای جلوگیری از مشکل رندر)
| موضوع | قاعده |
|---|---|
| **پروژه** | Godot 4.3؛ رزولوشن پایه **1280×720** (افقی)؛ Stretch: `canvas_items`، Aspect: `expand`؛ منطقهٔ امن UI ۴٪ از لبه‌ها |
| **رندر** | `gl_compatibility` برای موبایل؛ MSAA خاموش؛ فیلتر بافت **Linear + mipmaps** (هنر نقاشی)؛ pixel‑snap خاموش |
| **فرمت** | PNG با آلفا (stage مرجع)؛ در ایمپورت: موبایل → **VRAM Compressed (ETC2/ASTC)** برای پس‌زمینه‌ها، **Lossless** برای رابط و اسپرایت‌های کوچک؛ **Premultiplied alpha خاموش** مگر افکت جمع‌شونده |
| **اندازه بافت** | هر فایل ≤ 2048 در یک بُعد برای اسپرایت؛ پس‌زمینه تکه‌تکه (۱۰۲۴ یا ۲۰۴۸)؛ هیچ بافت > 4096 |
| **اطلس** | هر پارت → اطلس ۲۰۴۸×۲۰۴۸ (`tools/art/pack_atlas.py`، ماجول بعدی)؛ فاصلهٔ ۲ پیکسل؛ `AtlasTexture` یا `SpriteFrames` |
| **پردازش** | خط لولهٔ بازی: برش (`slice_sheets.py`) ← تمیز ← اطلس ← ایمپورت؛ **کد فقط جانگهدار نیست** هنر کانسپتِ تأییدشده است |
| **متن** | هرگز در تصویر؛ از `strings_fa.json` و فونت RTL؛ برچسب‌ها `Label` با `TextServerAdvanced` |
| **UI** | **۹-برش** با `NinePatchRect`/`StyleBoxTexture`؛ لبهٔ پچ پیش‌فرض ۴۰px (دکمه‌ها ۳۶، پنل ۶۰)؛ دکمه ۳ حالت: normal/pressed/disabled (تغییر رنگ با `modulate` + ۴٪ فشردگی) |
| **انیمیشن** | `AnimatedSprite2D` + `SpriteFrames` یا `AnimationPlayer` با tween؛ جابه‌جایی/مقیاس/چرخش با ماژول‌ها؛ **انیمیشن اسکلتی** برای غول‌ها (قطعات جدا) |
| **افکت** | `CPUParticles2D` برای موبایل؛ ذرات با اسپرایت‌های P8؛ افکت نور: `CanvasItemMaterial` blend **Add**؛ تعداد هم‌زمان ≤ ۱۶ |
| **دو زمان** | **دو لایه یک هندسه:** صحنهٔ «حال» و «گذشته» با **یک چیدمان**؛ لایهٔ غایب = شبح با alpha 0.35 + shader تینت (نارنجی=حال، آبی=گذشته)؛ **افکت لنز = shader دایره‌ای در Godot، نه تصویر** |
| **پارالاکس** | `ParallaxBackground` با ۵ لایه: آسمان ۰٫۰۵ · دور ۰٫۲ · میانه ۰٫۴ · نزدیک ۰٫۷ · پیش‌زمینه ۱٫۱؛ هر لایه افقی **بدون درز** (تکرارپذیر) |
| **برخورد** | **هرگز از شکل تصویر**؛ `CollisionShape2D` جدا (کپسول/مستطیل)؛ هیت‌باکس سلاح جدا از اسپرایت |
| **محور (pivot)** | شخصیت: **مرکز-پایین** (پا)؛ پرتابه/جلوه: مرکز؛ سلاح در دست: انتهای دسته |
| **سایه** | سایهٔ گرد زیر پا **در Godot** (`Sprite2D` شفاف)، در تصویر نباشد |
| **جهت** | همهٔ شخصیت‌ها فقط **رو به راست** ساخته می‌شوند؛ چپ = `flip_h` (افکت‌های نامتقارن استثنا) |
| **ترتیب لایه** | پس‌زمینه ← زمین ← اشیای صحنه ← دشمن/بازیکن ← پیش‌زمینه ← افکت ← UI |
| **عملکرد** | ≤ ۲۰۰ draw call؛ اسپرایت متحرک ≤ ۱۲ فریم در ثانیه (جز افکت ۲۴)؛ بدون `modulate` در سطح صحنهٔ بزرگ |
| **صدا و لرزش** | «حالت آرام» (لرزش/فلش) برای کودک؛ فلش پیاپی ممنوع |

## ۴. روش «لایه‌های هم‌خوان» برای صحنه‌ها (حیاتی)
هر صحنه در **دو نسخه با هندسهٔ یکسان**: `…_past` و `…_present` (موقعیت درخت/دروازه/پل ثابت)؛ جزئیات زنده روی لایهٔ جدا؛ سطوح قابل‌ایستادن در Godot با `TileMap`/`StaticBody2D`، نه از روی تصویر.

## ۵. گردش مدیر ← صاحب پروژه ← مدیر
1. مدیر در Canva طرح می‌سازد ← لینک در [`CANVA_LINKS.md`](CANVA_LINKS.md).
2. صاحب پروژه نسخهٔ کامل را در چت می‌فرستد.
3. مدیر با `tools/art/slice_sheets.py` برش می‌دهد، `draft` می‌زند و طرح بعدی را آماده می‌کند.
4. Claude Code با تصویر برش‌خورده می‌سازد و اسکرین‌شات کنار طرح مقایسه می‌شود.
