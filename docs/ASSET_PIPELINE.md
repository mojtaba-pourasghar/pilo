# خط تولید دارایی‌های هنری و نام‌گذاری

> هدف: همهٔ دارایی‌ها در مخزن با **نام‌گذاری ثابت** و **فهرست یکتا** باشند تا Claude Code فقط با خواندن فهرست بتواند بازی را بنویسد.

## ۱. فهرست یکتا
- **`assets/manifest/assets.csv`** (ساخته‌شده با `python3 tools/art/build_asset_manifest.py`): هر ردیف یک فایل: `id, part, priority, name_fa, category, spec, size, path, status, note`.
- **`status`:** `todo` ← `draft` (پیش‌نویس) ← `final` (تأیید صاحب پروژه).
- **`priority`:** **P0** = برش عمودی فصل ۱ (برای T8)، **P1** = پردهٔ ۱ (فصل ۱–۵)، **P2** = بقیه.
- Claude Code فقط از دارایی‌هایی استفاده می‌کند که `final` یا `draft` هستند؛ نبودن ← جانگهدار در `art/drafts/` + درخواست در `comms/ART_REQUESTS.md`.

## ۲. نام‌گذاری
`<پارت>_<دسته>_<نام>_<حالت>[_<شکل/سطح>].png` با حروف کوچک ASCII و زیرخط.
مثال‌ها: `p1_hero_arsam_run`، `p2_comp_pilo_f2_command`، `p3_tool_mirror_icon_l3`، `p4_wpn_lens_bow_l5_held`، `p5_enemy_saye_panje_attack`، `p6_ch01_forest_past_far`، `p8_fx_time_lens`، `p9_screen_hub`.

## ۳. پوشه‌ها
`assets/art/<پارت>/<id>.png` (پارت‌ها: `p1_heroes`، `p2_companions`، `p3_tools`، `p4_weapons`، `p5_enemies`، `p6_scenes`، `p7_living`، `p8_fx`، `p9_ui`، `p10_preview`). اسپرایت‌شیت: فریم‌ها افقی، اندازهٔ فریم در `spec/size`؛ فایل جانبی `*.json` (فریم، fps، pivot) کنار آن.
- شیت‌های ترکیبی (چند حالت در یک تصویر) مجازند ولی باید در manifest شناسهٔ تک‌تک حالت‌ها به یک `atlas` اشاره کنند (ستون `note: atlas=...`).

## ۴. ابزار تولید
- **Canva** (اتصال موجود): ساخت طراحی، صادرات PNG، ذخیره در مخزن. برای ثبات، هر پارت با **قالب/برگهٔ مرجع** شروع می‌شود (طراحی مرجع شخصیت → حالت‌ها).
- **tools/art/** (FLUX/Gemini): جایگزین برای تولید خودکار.
- **مرز:** هیچ تصویر بازی دیگر به ابزار داده نمی‌شود؛ پرامپت‌ها متنی هستند.
- **عکس کودک:** در مخزن نمی‌ماند.

## ۵. ورود به مخزن
1. تصویر `assets/art/<پارت>/<id>.png` + `status` در csv (`python3 tools/art/set_status.py draft <id>`).
2. فهرست خلاصه: `docs/ASSET_LIST.md` (ساخته‌شده توسط اسکریپت).
3. کامیت «هنر پارت N: …»؛ قبل از ادغام `final` توسط صاحب پروژه.
